## 3. 关键结论摘要

### 3.1 接口可用性与鉴权门槛

1. 上游 API 基址 `https://api.xiaoheihe.cn`，Web 端签名机制为 **hkey 7 位签名 + 一组公共 query 参数**。缺少 `_time` 会直接返回 `{"msg":"缺少必要参数[_time]","status":"failed"}` **【实测 report2/structures.md】**。
2. hkey 算法在 `crates/xhh-core/src/hkey.rs` 中有完整实现与 2 个回归向量。本次用独立 Python 复刻（不依赖 Rust 编译）后再与回归向量对齐、并用真实请求验证通过，**该算法可直接复用** **【源码 + 实测】**。
3. **匿名（无 Cookie）即可读取**：综合信息流、社区帖子列表、社区头条列表、社区目录、社区详情、通用搜索、用户主页、用户动态、关注/粉丝列表、Emoji、搜索发现、登录二维码、扫码状态 **【实测 report2–report8】**。
4. **必须登录**：帖子详情 `/bbs/app/link/tree`（匿名返回 `status:"show_captcha"`）、收藏夹 `/bbs/app/profile/fav/folders`（返回 `status:"login"`）、小程序搜索 **【实测】**。
5. **会话失效的判定信号是 HTTP 200 + body `status` 字段**，不是 HTTP 状态码。已观察到的取值：`ok` / `failed` / `login`（`msg:"请登录后使用该功能"`）/ `show_captcha` **【实测】**；另有 `lack_token`（token 过期后重放一次）**【网页】**。
6. 覆盖率对比：`xhh-core` 封装了 **35 个**不同上游路径（脚本统计）；官方网页版 JS 产物中出现 **86 个**不同后端路径（后者还包含游戏详情、PC 客户端下载等非社区类接口）。→ 上游项目**覆盖不到网页端的一半**，且本需求最关键的**社区目录、社区详情、社区头条、登录态检查**都不在其中。

### 3.2 社区／分区数据模型（本次调研最重要的更正）

一篇帖子同时携带 **四类互不相同的分类信息**，必须区分：

| 字段 | 含义 | 证据 |
|---|---|---|
| `topics[]`（元素含 `topic_id`/`name`/`pic_url`/`app_id`/`hot_value_v2`） | **真实社区归属**，服务端返回，**一篇帖子可以有多个**（实测观察到 1–2 个，最多见 2 个） | **【实测】** 综合流中 `(43,748366)`、`(53182,608630)` 等多社区样本 |
| `link_tag`（整数） | **内容形态，不是社区分区**：`1=视频贴`、`11=文章`、`27=图文`、`28=新动态分区` | **【网页】** `webjs/index-D_mYS5_Z.js` 中存在枚举 `e[e.视频贴=1] / e[e.新动态分区=28] / e[e.图文=27] / e[e.文章=11]` |
| `hashtags[]`（元素含 `hashtag_id`/`name`） | 话题标签（哈希标签），与社区无关 | **【实测】** 字段结构 |
| `list_content_tags[]` / `content_tags[]` / `act_hashtags[]` | 展示用标签 / 活动标签，用于 UI 渲染 | **【实测】** 字段结构 |

> ⚠️ **上游源码注释有误**：`crates/xhh-core/src/api/post.rs` 把 `link_tag` 注释为"分区 ID（默认 28=盒友杂谈，社区模式 27）"。网页端枚举显示 `link_tag` 是**内容形态**，`topic_ids` 才是社区。接入时不要沿用该注释。

其它已确认字段：
- `content_type`：`4` = 普通帖子；`1` = 头条列表条目；**`18` = 非帖子卡片（广告/推荐位，无 `linkid`、无 `link_tag`）**。网页端首页会显式剔除：`filter(t => t.content_type !== 18)` **【网页 + 实测】**。
- `topics[]` 为空数组的条目确实存在（综合流每页 1–3 条）→ 过滤逻辑必须处理"无社区信息"的情况。

### 3.3 社区过滤（核心需求的结论）

| 问题 | 结论 |
|---|---|
| 接口是否支持按社区 ID 请求？ | **支持，但仅单值**。`/bbs/app/topic/feeds?topic_id=` 与 `/bbs/app/topic/feeds/news?topic_id=` **【实测】**。 |
| 是否支持一次选择多个社区？ | **不支持**。`/bbs/app/topic/feeds` 传重复 `topic_id=7214&topic_id=425422` 时返回 17 条**全部属于 7214、0 条属于 425422**（服务端只取一个值）**【实测 report8】**。 |
| 是否提供服务端排除分区的参数？ | **【未找到】**。在网页端 80 个 JS 产物中检索 `exclude_topic`、`block_topic`、`filter_topic`、`屏蔽` **全部未找到**；`/bbs/app/feeds` 也不接受该类参数（负对照测试：伪造的排除参数被静默忽略）**【实测 report3 + 网页 grep】**。 |
| 每篇帖子是否稳定返回社区 ID？ | **是**，`topics[].topic_id` 稳定存在；但**可能为空数组**（广告卡/部分条目），**也可能属于多个社区**。 |
| "真实社区分区"与客户端推断标签 | `topics[].topic_id` = 真实社区归属；`link_tag` = 内容形态；`hashtags[].hashtag_id` = 话题标签。三者不可混用。 |

**关键行为差异（决定架构）**：

| 接口 | 归属严格性 | 确定性 | 分页 |
|---|---|---|---|
| `/bbs/app/feeds`（综合流） | **不严格**：带 `topic_id` 时仅 3/11 命中该社区 → 是**软加权推荐**，不是过滤 | **非确定性**：两次完全相同请求交集 **0/10** | `offset`（网页端） |
| `/bbs/app/topic/feeds`（社区·社区 tab） | **严格**：5 个样本 **109/109** 全部命中 | **非确定性**：两次相同请求交集 **0/18** | `offset`（工作），`lastval` 恒为空 |
| `/bbs/app/topic/feeds/news`（社区·头条 tab） | 接近严格：**36/37**（1 条属于别社区） | **确定性**：两次请求 19/19 完全一致且**顺序一致**；第二页重复请求也完全一致 | **`lastval` 毫秒时间戳游标（有效）**；`offset` 被忽略 |

→ **"只看这些社区"应以 `/bbs/app/topic/feeds/news` 为主数据源**（唯一确定性 + 游标可靠），按选中社区并发 N 路拉取、本地归并去重；**"屏蔽这些社区"只能本地过滤**。
详见 [04-社区过滤方案与限制.md](04-社区过滤方案与限制.md)。

### 3.4 依赖与许可证

- `xhh-workshop` 采用 **GPL-3.0-only**（`Cargo.toml` `[workspace.package] license = "GPL-3.0-only"`，`LICENSE` 为 GPLv3 全文）。
- ⚠️ **许可证风险**：若我们的 Tauri 客户端**直接依赖或链接 `xhh-core`（Rust 静态链接）**，将触发 GPL-3.0 的传染性，整个客户端须以 GPL-3.0 兼容方式分发。**建议只参考算法与接口契约、自行重写实现，不直接引入该 crate**。详见 [03-xhh-core覆盖与复用.md](03-xhh-core覆盖与复用.md) 第 5 节。

## 4. 使用与合规提示

本次调研严格遵守以下边界，建议客户端实现时同样遵守：

1. **只做只读浏览与常规互动**：发帖/评论/点赞/收藏/关注等写入接口**本报告只做静态分析与参数结构说明，未实际提交**。
2. **不批量采集**：本次全部验证请求均在个位数/轮次范围内，单页 `limit` 取小值，未做全量爬取。
3. **不绕过限制**：帖子详情匿名返回 `show_captcha`（网页端对应腾讯 TCaptcha，appid `199251710`，见 `webjs/index-CnBGc0ax.js`）。本次**未尝试绕过**，已标记为待验证。
4. **凭据安全**：本报告与所有证据文件**不含任何真实 Cookie、pkey、token 或账号凭据**。示例中的 `device_id` 为本次随机生成的本地值，非任何真实用户指纹。
5. **上游项目未被修改**：`research/xhh-workshop/` 仅作只读克隆用于阅读（`--depth 1`）。

## 5. 一句话结论

上游接口对**匿名只读浏览**足够友好，社区维度的**"多选包含"可以通过逐社区调用 `/bbs/app/topic/feeds/news` + 本地归并实现**；但**"多选屏蔽"以及综合流的社区过滤没有任何服务端支持，必须在客户端本地完成**，且要正视"综合流非确定性、`topic/feeds` 非确定性、`news` 列表覆盖不全"这三个硬约束。
