# 发布小黑盒盒更新

用户访问 [下载与更新页](https://cjbtj.xyz/xiaoheihehe/)。从 0.1.1 开始，客户端可在“设置 → 关于 → 检查更新”查看新版说明并下载安装包。下载后退出客户端，再运行安装包覆盖安装。检查更新不会自动运行安装程序。

## 地址与部署结构

| 地址／路径 | 用途 |
| --- | --- |
| `https://cjbtj.xyz/xiaoheihehe/` | 公共下载页 |
| `https://cjbtj.xyz/xiaoheihehe/api/version` | 最新稳定版本 JSON，禁止缓存 |
| `https://cjbtj.xyz/xiaoheihehe/releases/<版本>/xiaoheihehe_<版本>_x64-setup.exe` | 版本安装包 |
| `/opt/xiaoheihehe-updates/` | 页面、版本清单、安装包和发布工具 |
| `/etc/nginx/snippets/xiaoheihehe-updates.conf` | HTTPS 路由配置 |
| `/var/backups/xiaoheihehe-updates/` | 配置备份 |

服务由现有 Nginx 提供，无额外端口或后台进程。仅添加 `/xiaoheihehe/` 路由；主站、轻语和中继路由保持原配置。发布通过 SSH 密钥认证，没有公开上传或管理接口。

客户端使用独立 Rust HTTP 客户端，不发送小黑盒账号、Cookie 或设置。连接超时 5 秒，总超时 12 秒，响应上限 64 KiB。清单校验稳定三段版本号、Windows x64 平台、限定下载地址和 SHA-256 格式。发布时核对文件哈希；客户端通过系统浏览器下载，由用户运行安装包，不自动校验浏览器下载文件。

## 发布新版本

同步增加以下项目版本：`package.json`、`package-lock.json` 根项目版本、`backend/Cargo.toml`、`src-tauri/Cargo.toml`、`src-tauri/tauri.conf.json`。采用 `主.次.补丁`，例如 `0.1.2`。Cargo 命令会更新锁文件中的本项目版本；关于页读取 package 版本，后端读取 Cargo 版本。

在项目根目录运行：

```powershell
npm run backend:test
npm run desktop:test
npm run desktop:build
./scripts/publish-update.ps1 -Notes '修复评论加载，改进社区浏览体验。'
```

默认目标为 `admin@47.92.7.207`，可用 `-Server` 指定其他 SSH 目标。脚本按项目版本定位安装包，校验产品名和版本，生成带大小、SHA-256 和 UTC 日期的清单。服务器验证文件后先保存安装包，再原子切换 `latest.json`，保留历史版本。公网清单核验成功才报告完成。

`scripts/publish-update.ps1` 使用带 BOM 的 UTF-8 编码，兼容 Windows PowerShell 对中文产品名与安装包路径的读取。

同一版本已有不同文件时拒绝覆盖；最新版本不得降级。修改程序后必须增加版本号。同一文件可重复发布；发布锁避免并发覆盖。历史清单保存在 `releases/<版本>/manifest.json`。

只有用户明确要求保持版本号时才人工替换同版本安装包：核对线上旧包哈希，持有发布锁，将旧安装包和清单备份到 `/var/backups/xiaoheihehe-updates/`，再原子替换安装包和清单。常规发布脚本仍拒绝同版本覆盖。客户端下载比较版本号，因此同版本重打包不会提示有新版本，需重新下载覆盖安装。下载页以安装包 SHA-256 为查询参数区分不同构建；安装包响应禁止缓存，避免沿用旧包。

## 部署或更新配置

```powershell
scp -r deploy/update-service admin@47.92.7.207:/tmp/heybox-update-service
ssh admin@47.92.7.207 'sudo -n bash /tmp/heybox-update-service/install.sh'
```

脚本定位现有 `cjbtj.xyz` 站点，幂等插入更新配置 include。修改前备份站点和已有更新配置，`nginx -t` 成功后平滑重载；校验失败恢复配置。下载页内部重写到明确的 `index.html` 文件地址，避免目录地址触发文件 alias 索引错误。

初始站点备份：`/var/backups/xiaoheihehe-updates/initial-20261011/cjbtj.xyz.before`。后续每次部署使用独立 UTC 时间目录。移除服务时仅移除站点中的更新 include，检查并重载 Nginx，保留其他站点配置与历史安装包。

## 验证与排障

```powershell
Invoke-RestMethod https://cjbtj.xyz/xiaoheihehe/api/version
Invoke-WebRequest https://cjbtj.xyz/xiaoheihehe/ -Method Head
ssh admin@47.92.7.207 'sudo -n nginx -t'
```

客户端失败时显示错误并允许重试，下载页失败时提示刷新。未知路径返回 404；公共接口写请求返回 403。

验证结果：后端 26 项、桌面 4 项、发布工具 3 项测试通过；0.1.1 Windows x64 安装包构建成功（约 3.08 MiB）。在线客户端检查读取真实版本；模拟新版、失败、重试流程正常。公网安装包实际下载后的大小与 SHA-256 匹配清单，下载页展示真实版本。主站和轻语版本 API 仍为 200，中继指标仍为 404。

0.1.4 发布（2026-10-17）：后端 30 项、桌面 4 项测试通过，`scripts/check-comment-images.cjs` 13 项、`check-window-width.cjs` 9 项、`check-window-height.cjs` 8 项浏览器检查通过，`CommentImageCheck` 只读实测通过；安装包 3,244,133 字节，SHA-256 `2949ed257f5fd0a1058a6873d2999c33f9a649b141dca2e88d2399b74aed5d5c`，GitHub Releases 与服务器下载页两处下载所得文件均为该哈希与 `ProductVersion 0.1.4`；公开清单返回 `version=0.1.4`、`platform=windows-x86_64`，0.1.3 历史安装包仍为 200。未在本机执行静默安装，打包产物的安装与运行未实测。

构建环境注意：本机 `%LOCALAPPDATA%\tauri\NSIS` 缓存缺失时，Tauri CLI 直接从 GitHub 下载 `nsis-3.11.zip` 会超时或连接被重置（实测 `timeout: global`）。可先用 `gh release download nsis-3.11 --repo tauri-apps/binary-releases --pattern nsis-3.11.zip` 下载，解压为 `%LOCALAPPDATA%\tauri\NSIS`（内含 `Bin/makensis.exe`）后重新执行 `npm run desktop:build`，打包步骤即可完成。
