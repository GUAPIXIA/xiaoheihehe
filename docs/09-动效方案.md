# 动效方案

目标：让程序从「窗口里的网页」变成「有空间感的桌面客户端」。只补三类东西——空间连续性、加载感、操作反馈；不加装饰。

状态：草案，待评审。本文只定义方案、参数与验收标准，不改代码；评审通过后按第 8 节分批实现。

一句话版本：先做 5 个 P0——页面与图片的「展开／收回」、点赞收藏反馈、骨架屏、浮层退场；参数、技术方案与验收标准见第 3–7 节。

适用版本：0.1.6 之后（0.1.7 或独立动效版本）。

## 1. 基线

技术前提：Tauri 2 + React 19 + TypeScript 5.7，无动画库；本机 WebView2 157.0.4341.42（Chromium 157，原生支持 View Transitions API）。

现有开关与兜底：

- `Preferences.animations` 默认 `true`（`src/settingsDefaults.ts`），关闭时根节点加 `.no-motion`，由 `src/styles.css` 全局禁用 `animation` 与 `transition`。
- 系统 `prefers-reduced-motion: reduce` 时同样全局禁用 CSS 动画；目前只有 `scrollDetail` 在 JS 里主动判断了这一点（`src/App.tsx`，`scrollDetail`）。

现有动效只有三个原语和两处零散过渡：

| 现有 | 位置 | 参数 |
| --- | --- | --- |
| `appear` 淡入 | 下拉菜单、Modal 背景、Toast | 130ms |
| `popup` 弹窗入场 | `.modal` | 160ms，`translateY(5px) scale(.985)` |
| `spin` 旋转 | 刷新按钮 | 900ms linear |
| 开关滑块 | `.switch span` | 150ms |
| 图片 hover | 配图放大图标、评论图 | 150ms 透明度 |
| 平滑滚动 | 详情内跳评论区等 | 仅开启动画时 |

现状问题，按收益排序：

| # | 问题 | 表现 |
| --- | --- | --- |
| 1 | 页面硬切换 | 点开帖子、返回、进盒友主页、开大图，整页瞬间替换，没有空间关系 |
| 2 | 加载无形状 | 只有一行「正在读取…」，内容加载完突然铺满 |
| 3 | 操作无手感 | 点赞、收藏只变色，点完像没点 |
| 4 | 图片硬弹出 | 配图、评论图、头像没有渐显 |
| 5 | 浮层有进无出 | Modal、Toast、下拉菜单关闭瞬间消失 |
| 6 | 次级切换瞬移 | 设置 tab、表情面板、评论框吸附、查看器切图 |

## 2. 原则

1. **每个动效回答一个变化问题**：我从哪里来、我点了什么、现在发生了什么。答不上的不加。
2. **只在状态切换时动，不对内容做逐个入场**。列表分页、刷新时不重播任何入场动画；不做卡片 stagger。
3. **只动 transform 和 opacity**。不动宽高、`top/left`、`filter`、阴影、背景渐变位置；例外只在第 4.6 节明确写出。
4. **一次一个主角**：同一时刻只有一个显著动效，其他元素只做淡入淡出。
5. **短**：面板与页面 ≤ 240ms，微反馈 ≤ 160ms。640px 的密集信息流里，长动画会打断阅读。
6. **可关闭、可降级、防连点**：动画关闭、系统减少动态、旧 WebView2、快速连续点击，都必须有明确行为，不能卡住、不能排队。
7. **保持官方客户端的气质**：安静、密、克制。允许的唯一「活泼」是点赞的轻弹。

## 3. 动效令牌

统一放在 `.desktop-stage` 上（与现有主题变量同级），实现时加在 `src/styles.css`。

```css
.desktop-stage {
  --motion-fast: 120ms;   /* 颜色、数字、hover/按压 */
  --motion-base: 180ms;   /* 面板、详情入场、dock */
  --motion-slow: 240ms;   /* 共享元素 morph、主题 */
  --motion-press: 80ms;   /* 按下缩放 */
  --motion-ease-out: cubic-bezier(.2, .7, .2, 1);
  --motion-ease-in-out: cubic-bezier(.4, 0, .2, 1);
  --motion-ease-pop: cubic-bezier(.34, 1.56, .64, 1);
  --motion-rise: 6px;     /* 面板入场位移 */
  --motion-rise-sm: 3px;  /* 数字/文字切换位移 */
}
```

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--motion-fast` | 120ms | hover 颜色、点赞数字、tab 淡入 |
| `--motion-base` | 180ms | Modal、详情、dock、Toast 进出 |
| `--motion-slow` | 240ms | 共享元素展开/收回、主题 crossfade |
| `--motion-press` | 80ms | 按钮按下缩放 |
| `--motion-ease-out` | `cubic-bezier(.2,.7,.2,1)` | 默认，所有入场 |
| `--motion-ease-in-out` | `cubic-bezier(.4,0,.2,1)` | 进出对称的 crossfade |
| `--motion-ease-pop` | `cubic-bezier(.34,1.56,.64,1)` | 仅点赞/收藏的轻弹 |

动效开关与 `prefers-reduced-motion` 继续由现有全局规则兜底；新加的 JS 动效必须自己判断（见 6.3）。

## 4. 逐项方案

### 4.1 导航转场（P0，签名动作）

**核心动作：纸张展开 / 收回。** 列表里的图文帖封面长成详情页顶部大图，返回时原路收回。这是全程序唯一允许的「共享元素」动效，其余导航全部是交叉淡入。

| 场景 | 动效 | 时长 |
| --- | --- | --- |
| 首页/列表 → 图文帖详情 | 封面图 morph 到详情大图；其余内容交叉淡入 | morph 240ms，其余 180ms |
| 首页/列表 → 纯文字帖详情 | 整体交叉淡入 + 详情上移 6px，不做标题 morph | 180ms |
| 详情 → 返回列表 | 反向 morph 回原卡片封面，同时恢复进入前滚动位置 | 240ms |
| 列表 → 盒友主页 | 走 4.5 的 Modal 进出场，不做 morph | 160ms / 140ms |
| 主页 → 打开帖子 | Modal 淡出 + 详情淡入（顺序执行） | 140ms + 180ms |
| 切换「我的收藏 / 浏览记录」 | 仅列表交叉淡入；标题与列表一起 | 180ms |

实现要点：

- 用原生 View Transitions API：`document.startViewTransition(() => flushSync(update))`。TypeScript 5.7 的 `lib.dom` 已包含 `ViewTransition` 类型，不需要声明补丁。
- **根节点只做透明度，不做位移**。根快照包含顶部 titlebar；位移会让整条标题栏跟着动，穿帮。详情入场位移放在 `.post-detail` 的降级动画里。
- **返回时滚动恢复必须在 `flushSync` 内完成**。现有 `useLayoutEffect` 在 `selected` 变 `null` 时恢复 `listScroll`（`src/App.tsx`），`flushSync` 会同步执行它，因此新快照里的列表已经在正确滚动位置，morph 的两端才对齐。
- 共享元素只命名两端实际存在的元素，且**同一时刻全页面只能有一个同名元素**。v1 只做图文帖（`selected.kind === '图文'` 且有封面图）；纯文字帖的标题 morph（17px → 23px 文字被拉伸）先不做，等 spike 评估。
- 名称生命周期：

| 名称 | 用在哪 | 何时加 | 何时清 |
| --- | --- | --- | --- |
| `vt-post-hero` | 卡片封面 `<img>`、详情顶部 `.image-gallery` 内 `<img>` | 打开前给卡片图加；详情图用静态 CSS 名称；返回时在 `flushSync` 之后、快照前给目标卡片图加 | `transition.finished` 后移除内联样式 |
| `vt-image` | 缩略图、查看器大图（见 4.2） | 同上 | 同上 |

- 降级：不支持 View Transitions、动画关闭、系统减少动态时，直接更新状态；详情用 CSS `detail-enter`（180ms 淡入 + 6px 上移），列表不做退场。
- **防连点**：模块级记录正在运行的 transition；有正在运行的 transition 时直接普通更新，不排队。返回、切页、开图、开主页共用这一个守卫。
- **缩放容器风险**：窗口整体套了 `transform: scale(fit)`（`.window-inner`，`src/App.tsx`）。v1 只在 `fit === 1` 时启用 morph，其余缩放比例退化为交叉淡入；等 spike 在 50%–300% 下实测稳定后再放开。桌面端 100% 且屏幕放得下时 `fit` 正好是 1，覆盖主场景。
- 只在事件处理器里触发，不放在 effect 里（StrictMode 下 effect 会执行两次）。

验收：

- 打开图文帖，封面从卡片位置连续长到详情顶部，无白闪、无跳位；返回时反向收回，列表滚动位置与进入前一致（0px 误差）。
- 纯文字帖只有交叉淡入，不出现标题拉伸。
- 连续快速点开/返回 10 次，不残留快照、不卡死、控制台无 View Transition 报错。
- 动画关闭 / 系统减少动态时，瞬间切换，功能不变。

### 4.2 图片查看器（P0）

和 4.1 同一套「纸张展开」语言：缩略图长成查看器大图，关闭时收回。

| 动作 | 动效 | 时长 |
| --- | --- | --- |
| 打开（首页卡片 / 详情画廊 / 正文图 / 评论图） | 缩略图 morph 到查看器图片；背景遮罩淡入；查看器面板不做 popup | morph 240ms，遮罩 140ms |
| 关闭 | 大图 morph 回原缩略图；遮罩淡出 | 240ms / 140ms |
| 找不到源缩略图（列表已刷新等） | 整体交叉淡入淡出 | 160ms |

实现要点：

- Modal 增加 `variant="image"`：查看器面板不加 `.modal` 的 `popup` 动画，避免「面板弹一下」和「图片 morph」两个主角打架；背景遮罩只做透明度。
- 打开时给被点缩略图加 `vt-image`；查看器大图用静态 CSS 名称。关闭时 `image` 置空，旧快照里的大图有名称，新快照里需要临时给源缩略图加名称——在 `flushSync` 之后、快照前执行，`transition.finished` 后清理。
- 保存源缩略图元素引用；元素已脱离文档时走整体交叉降级。
- 大图可能尚未解码：若 morph 到空白，保持 `--soft` 背景并在 `onLoad` 后 150ms 淡入，不能闪白。
- 评论图、正文图复用同一套逻辑；图片来源是 `comment` 时同样处理。

验收：

- 从首页单图、三图、详情大图、评论区图片打开，起点都对准被点缩略图，终点是大图查看器；关闭回到正确缩略图。
- 打开期间左右切图、滚轮缩放、拖拽、双击原始大小、Esc、方向键都不受影响。
- 图片加载慢时先显示软色背景再淡入，不出现白块。

### 4.3 点赞与收藏（P0）

| 操作 | 反馈 | 时长 |
| --- | --- | --- |
| 帖子点赞（进入已赞） | 图标 `scale 1 → 1.18 → 1`；数字上移淡入 | 160ms / 120ms |
| 取消点赞 | 图标与数字颜色 120ms 过渡，不弹 | 120ms |
| 收藏（进入已收藏） | 图标轻弹 + 填充淡入（现有 `fill` 保留） | 160ms |
| 取消收藏 | 颜色过渡，不弹 | 120ms |
| 评论点赞 | 同上，图标幅度 1.12 | 160ms / 120ms |
| 请求失败回滚 | 数字变化照常触发 120ms 切换，表示状态确实还原；Toast 不变 | 120ms |

实现要点：

- 弹只在新状态是「已赞 / 已藏」时播放。用 App 里的短时标记（如 `pop: { kind: 'like' | 'save', id: number }`，200ms 后清除）决定是否加 `.is-popping`；不要用「每次渲染都播放」的 class，否则列表刷新、分页都会重播。
- 数字用 `key={count}` 触发 `count-swap`（`opacity .25 → 1`、`translateY(3px) → 0`），只在数值变化时播放；失败回滚也会播放，这是预期。
- 动画只作用于图标 `<svg>` 和数字 `<span>`，不改变按钮尺寸，不产生布局位移。
- 评论点赞的乐观更新与回滚逻辑保持不变（`src/App.tsx` 的 `likeComment`），只加视觉反馈。

验收：

- 点赞后立刻出现轻弹和数字切换；取消只有颜色变化；失败回滚时数字回到原值且带切换。
- 列表刷新、字体缩放、翻页、收藏页切换时不重播动画。
- 按钮 `aria-pressed`、键盘操作、禁用态不受影响。

### 4.4 加载与骨架屏（P0）

原则：等待时内容应该有形状，而不是一行字。骨架屏不做夸张 shimmer，只做低对比度扫光。

| 位置 | 骨架 | 备注 |
| --- | --- | --- |
| 首页 / 收藏 / 浏览记录首次加载 | 3 张卡片：头像行、标题 80%、摘要两行、可选图片块 | 与真实卡片同样的左右内边距和间距 |
| 评论首次加载 | 3 行：27px 头像、作者行、两行正文、时间行 | 与 `.comment` 布局一致 |
| 图片加载 | 保持现有文字提示 | 查看器内不做骨架 |
| 图片内容 | `opacity 0 → 1` 150ms | 帖子配图、正文图、评论图、查看器大图；头像和徽章不做 |

实现要点：

- **延迟 120ms 再显示骨架**：缓存命中或接口秒回时不闪。加载在 120ms 内结束时直接出内容。
- 骨架容器 `aria-hidden="true"`；同时保留一个视觉隐藏的 `role="status"` 文本（新增 `.sr-only` 工具类）描述「正在读取…」，读屏体验不退化。
- 扫光用伪元素 `translateX(-100% → 100%)` 的 transform 实现，1.2s linear 无限循环；动画关闭 / 减少动态时只显示静态软色块。
- 图片渐显用 `onLoad` 给元素加 `data-loaded`（`classList` 直接操作，避免整卡片重渲染）；CSP 不变。列表里 `loading="lazy"` 的图片也适用。
- 不改现有「没有更多」「重试」「失败占位」逻辑。

验收：

- DevTools 节流 Slow 3G：先出现骨架（约 120ms 后），数据到达后骨架消失、内容出现，无闪烁、无空白跳动。
- 本地缓存命中快速切换列表：不出现骨架闪一下。
- 图片加载中占位为软色，加载完 150ms 渐显，不白块。
- 读屏仍能听到加载状态；动画关闭时骨架静止。

### 4.5 浮层进出场（P0）

覆盖 Modal（设置、账号、盒友主页）、Toast、下拉菜单、表情面板。现在这些浮层全是「有进无出」，关闭生硬。

| 浮层 | 入场 | 退场 |
| --- | --- | --- |
| Modal 面板 | `opacity 0→1`、`translateY(5px) scale(.985) → 1`，160ms `ease-out` | `opacity 1→0`、`translateY(4px) scale(.99)`，140ms |
| Modal 背景 | 透明度 140ms（blur 保持静态，不做 filter 动画） | 透明度 120ms |
| Toast | 透明度 140ms + 上移 4px | 透明度 160ms + 下移 4px |
| 下拉菜单 | 透明度 120ms + 上移 3px | 透明度 100ms |
| 表情面板 | 透明度 120ms | 不做退场（在文档流内，退出会带动高度塌陷） |

实现要点：

- 新增 `usePresence(open, exitMs)`（见 6.2）：`open` 变 `false` 后先加 `.is-closing` 播退场，140–160ms 后再真正卸载。设置、账号、主页三个 Modal 以及 Toast、菜单共用；图片查看器见 4.2。
- 退场期间禁用交互：背景点击、Esc、关闭按钮都忽略，避免重复触发。
- 焦点：焦点陷阱与 `Modal` 卸载时恢复焦点的逻辑保持不变；恢复会晚 140ms，可接受。
- 图片查看器是例外：面板不做 popup，退场交给 4.2 的 morph。
- Toast 最近一次消息覆盖前一条：新消息出现时取消上一条的退场计时，重新计 3000ms 展示 + 160ms 退出。
- 下拉菜单点击外部关闭同样走退场；菜单遮罩 `.menu-dismiss` 一并淡出。
- 动画关闭 / 减少动态时：直接卸载，无退场。

验收：

- 打开/关闭设置、账号、主页：面板和背景都淡入淡出，无「瞬间消失」；连续快速开关不残留、不叠加。
- Toast 连续触发多条：只显示最新一条，3s 后淡出；不出现两条同时存在。
- 菜单点击项、点空白、再点按钮三种关闭方式行为一致。
- 焦点陷阱和 Esc 行为不回归；关闭后焦点回到触发按钮。

### 4.6 评论框吸附（P1）

评论框从文档流末尾「吸附」到窗口底部时，现在是瞬间跳变；吸附期间右下角的缩放、回到顶部、跳评论按钮会突然上移（`--reply-dock-lift`）。

| 动作 | 动效 | 时长 |
| --- | --- | --- |
| 吸附进入 | 表单上移 10px + 淡入；上方阴影淡入 | 180ms |
| 收起 | 不做退场（表单要回到文档流末尾，跨位置收回会穿帮） | — |
| 浮动按钮让位 | `bottom` 过渡到新位置 | 180ms |

实现要点：

- 只在 `composerDocked` 变化的瞬间给 `.desktop-stage` 加一个短暂的 `is-docking` 类（约 240ms），由它启用 `.zoom-control`、`.detail-navigation` 的 `bottom`/`transform` 过渡。**不要常开**：`ResizeObserver` 会在输入、展开表情面板时持续修改 `--reply-dock-lift`，常开会让按钮全程拖尾。
- 收起不做动画，避免表单从底部飞回列表末尾的怪异位移；收起后原来的滚动位置和布局保持不变。
- 动画只影响吸附表单自身和浮动按钮，不改变 `--reply-dock-lift` 的计算逻辑。

验收：

- 点帖子评论按钮、点某条评论的回复：评论框从底部滑入并聚焦，右下角按钮同步让位，无跳动。
- 输入、展开/收起表情面板、发送成功、Esc 收起均正常；按钮不拖影。
- 动画关闭时瞬间吸附，功能不变。

### 4.7 设置 tab 与查看器切图（P1）

| 动作 | 动效 | 时长 |
| --- | --- | --- |
| 设置侧栏切换 | 内容淡入 + 上移 3px | 120ms |
| 查看器左右切图 | 新图淡入 + 轻微缩放（`1.01 → 1`） | 140ms |
| 开关、单选、主题选中 | 仅颜色/背景 120ms 过渡 | 120ms |

实现要点：

- 设置内容包一层 `key={settingsTab}` 的容器播放 `pane-in`；内容高度变化导致的 Modal 高度跳变不处理（做高度动画会引入布局动画，性价比低）。
- 切图淡入在图片元素重新挂载时触发：非展开模式作用于 `.gallery-image`，查看器内作用于重新挂载的 `.expanded-image`；拖拽、缩放中不播放（`ExpandedImage` 重新挂载本来就会重置视图，保持一致）。
- 切图不做横向滑动：查看器已经支持方向键与按钮，滑动动画会与缩放锚点逻辑冲突。

验收：

- 切 tab 不闪烁、不跳布局；查看器切图不影响缩放/拖拽状态。
- 动画关闭时立即切换。

### 4.8 主题切换（P1）

| 动作 | 动效 | 时长 |
| --- | --- | --- |
| 用户在设置里切浅色 / 深色 / 跟随系统 | 全局 crossfade | 200ms |
| 系统主题变化（跟随系统时） | 不播放动画，立即切换 | — |

实现要点：

- 用一次 View Transition 的 root crossfade 完成，避免给每个元素加 `transition` 造成大面积重绘。切换动作在主题按钮的点击处理器里触发（`flushSync`）。
- 跟随系统时由系统事件触发的变化不播动画，防止用户在其他应用里切换系统主题时本程序突然闪一下。
- 不支持 View Transition 或关闭动画时直接切换。
- 主题切换后图片不重新请求、滚动位置不变。

验收：

- 深色 ↔ 浅色 200ms 平滑过渡，无白闪、无局部残留旧颜色；图片、滚动位置、焦点不变。

### 4.9 指针反馈（P1）

现在大部分按钮 hover 是硬切颜色，点下去没有反馈。只补最基本的，不做卡片悬浮。

- 颜色/背景过渡 120ms，覆盖：`.icon-button`、`.window-control`、`.page-dropdown button`、`.post-actions button`、`.topic-tag`、`.secondary-button`、`.primary-button`、`.text-button`、`.settings-nav button`、`.gallery-arrow` 等（统一挂在按钮组，不逐个写）。
- 按下反馈：主要按钮、图标按钮、窗口控制、评论点赞按钮 `transform: scale(.97)`，80ms；松开回 1。不做在 `.post-card` 整体上，避免信息流发飘。
- 不改变 `:focus-visible` 外框、点击区域、布局尺寸。

验收：

- hover/按下有细微反馈但不喧宾夺主；移动端/触控不会出现卡住的 hover 态；焦点样式保持。

## 5. 不做清单

| 不做 | 原因 |
| --- | --- |
| 列表卡片逐个入场 / stagger 动画 | 分页和刷新会重播；这是最典型的模板化设计，与安静的气质冲突 |
| 卡片 hover 抬升、阴影悬浮 | 640px 密集列表里会让整页发飘，且触发大面积重绘 |
| 鼠标跟随、光晕、渐变边框、视差 | 装饰性，与官方客户端气质不符 |
| 全屏 spinner、骨架屏夸张扫光 | 廉价；本方案用低对比度骨架 |
| 页面横向滑动转场 | 窄窗口里容易裁切；本方案用展开/收回 |
| 数字 odometer 滚动 | 信息流里字太小，滚动反而难读；用 120ms 淡切 |
| 超过 250ms 的页面转场 | 打断阅读节奏 |
| 窗口级动画（最小化、关闭、托盘） | 由 Windows 管理，Tauri 窗口层不碰 |
| 给所有元素加 transition | 大面积重绘、互相干扰；只列具体选择器 |
| 声音、振动 | 桌面端非必要，且本程序无此先例 |

### 6.2 `motion.ts` 草案

```ts
import { flushSync } from 'react-dom';

let running: ViewTransition | null = null;

export function motionAllowed(preference: boolean): boolean {
  return preference && !window.matchMedia('(prefers-reduced-motion: reduce)').matches;
}

export function viewTransition(
  preference: boolean,
  update: () => void,
  hooks?: { before?: () => void; afterUpdate?: () => void; cleanup?: () => void },
): void {
  if (!motionAllowed(preference) || typeof document.startViewTransition !== 'function' || running) {
    update();
    return;
  }
  hooks?.before?.();
  const transition = document.startViewTransition(() => {
    flushSync(update);
    hooks?.afterUpdate?.();
  });
  running = transition;
  const done = () => { running = null; hooks?.cleanup?.(); };
  transition.finished.then(done, done);
}

export function pinTransitionName(target: Element | null, name: string): () => void {
  if (!(target instanceof HTMLElement)) return () => {};
  const previous = target.style.getPropertyValue('view-transition-name');
  target.style.setProperty('view-transition-name', name);
  return () => {
    if (previous) target.style.setProperty('view-transition-name', previous);
    else target.style.removeProperty('view-transition-name');
  };
}
```

`usePresence` 用于浮层（示意）：

```ts
export function usePresence(open: boolean, exitMs = 140) {
  const [mounted, setMounted] = useState(open);
  const [closing, setClosing] = useState(false);
  useEffect(() => {
    if (open) { setMounted(true); setClosing(false); return; }
    if (!mounted) return;
    setClosing(true);
    const timer = setTimeout(() => { setMounted(false); setClosing(false); }, exitMs);
    return () => clearTimeout(timer);
  }, [open, mounted, exitMs]);
  return { mounted, closing };
}
```

实现时以实际状态拆分为准：Modal、Toast、菜单各自持有 presence；不要把四个 Modal 合成一个统一开关，避免互相影响。

### 6.3 开关、降级与守卫

所有新动效按以下顺序判断：

1. `prefs.animations === false` → 全部关闭。
2. `prefers-reduced-motion: reduce` → 全部关闭（包括 View Transition；现有全局 CSS 规则管不到 `::view-transition-*` 伪元素，必须在 JS 里判断）。
3. `document.startViewTransition` 不存在 → morph 和主题 crossfade 退化为 CSS 淡入，其余 CSS 动效照常。
4. 正在运行的 View Transition 未结束 → 本次不排队，直接更新。
5. `fit !== 1`（窗口被缩放）→ v1 只用交叉淡入，不启用共享元素。
6. 有其它 Modal / 查看器打开时 → 导航转场降级为普通更新，避免快照里出现叠加浮层。

保留现有 `.no-motion` 和媒体查询规则，不移除；新 CSS 动画天然被它们覆盖。

同时把设置里「动画效果」的描述从「菜单与弹窗使用轻量过渡」改为「页面转场与轻量反馈」，与实际范围一致（`src/App.tsx` 设置页）。

### 6.4 性能

- 动画预算：单次转场 ≤ 240ms；同一时刻运行的显著动画 ≤ 2；只使用 compositor 友好的 `transform` / `opacity`。
- View Transition 会为整个页面拍两张快照，本程序 640px 窗口开销可接受；只用于离散的导航、主题切换，不用于滚动、输入、点赞等高频操作。
- 骨架屏最多 3 张卡片 / 3 行评论；扫光只作用于伪元素，避免大面积重绘。
- 图片渐显直接改 `classList`，不引发 React 重渲染；`onLoad` 对缓存图片同样会触发。
- 记录一次 Performance 面板：典型操作（打开帖子、开大图、切主题）无超过 50ms 的长任务；如不达标，优先砍共享元素，保留淡入。
- 不给 `will-change` 常驻；只在播放期间加类，结束后移除。

### 6.5 兼容性

- WebView2 Evergreen 已支持 `document.startViewTransition`（Chromium 111+）；本机 157。浏览器开发预览（Chrome/Edge）同样支持。
- CSP 现有配置允许内联样式（`style-src 'unsafe-inline'`），`view-transition-name` 内联设置不受影响；不新增任何网络请求或依赖。
- Windows「辅助功能 → 视觉效果 → 动画效果」关闭时，WebView2 会报告 `prefers-reduced-motion: reduce`，按 6.3 处理。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 缩放容器下 View Transition 快照错位/模糊 | 签名动作不成立 | v1 只在 `fit === 1` 启用；spike 通过后逐步放开；最低降级为交叉淡入 |
| 深色主题快照闪白 | 观感差 | 给 `::view-transition-old/new(root)` 设定透明背景并实测；仍闪则只在浅色启用，或放弃 VT |
| 大图未解码时 morph 到空白 | 闪白/闪软色 | 保持 `--soft` 背景，`onLoad` 后淡入；必要时先预解码再开查看器 |
| 快速连点导致转场排队/残留 | 卡死、快照错乱 | 全局单例守卫，运行中直接普通更新 |
| `--reply-dock-lift` 常开过渡导致按钮拖影 | dock 期间交互发黏 | 只在 `composerDocked` 变化时临时加 `is-docking` 类 |
| 列表刷新重播点赞/入场动画 | 干扰阅读 | 用交互标记和 `key=count`，不用「每次渲染都播放」的 class |
| StrictMode 开发期 effect 双跑 | 开发环境动画异常 | 所有 View Transition 只在事件处理器触发 |
| 骨架屏 120ms 内闪烁 | 界面抖动 | 延迟显示 + 数据到达直接替换 |
| Toast 计时器互相覆盖 | 旧计时器清掉新 Toast | 单一计时器引用，新消息重置 |
| 焦点恢复变晚 140ms | 键盘操作短暂失焦 | 退场期间保持焦点陷阱，卸载时统一恢复 |
